Graph Structure
The LearningGraph demonstrates several graph types:

DAG: Both skill prerequisites and course prerequisites form directed acyclic graphs (complementary views)

Bipartite: Learner-Skill and Course-Skill relationships

Weighted: Proficiency levels as edge weights

Multi-relational: Multiple edge types between node types

The LearningGraph demonstrates several graph types:

DAG: The prerequisite edges form a directed acyclic graph

Bipartite: Learner-Skill and Course-Skill relationships

Weighted: Proficiency levels as edge weights

Multi-relational: Multiple edge types between node types

Proficiency Framework
Work role requirements follow typical career progression:

Entry/Mid (2-5 yrs): concentration skills at level 2, supporting at 1-2

Mid (3-5 yrs): concentration skills at 2-3, supporting at 2

Senior (5+ yrs): concentration skills at 3, supporting at 2

Level 4 (Master) is reserved for thought leaders, not job requirements

Demonstrated Algorithms
Learning paths: Find minimal skill acquisition sequence from a learner's current profile to a target skill

Gap analysis: Compare current vs. required skill profiles

Community detection: Skills cluster by competency area

Centrality: Identify foundational vs. advanced skills

Topological sort: Determine valid learning orderings

Course Structure
The 15 courses are designed to cover all 18 skills with realistic prerequisites. Entry points (no prerequisites): C01 (Programming), C03 (Probability), C04 (Linear Algebra). The course DAG has 5 levels from entry points to capstone courses (C10, C14, C15).

Course design was inspired by curricula from Georgia Tech OMSA, UC Berkeley MIDS, Stanford MS Statistics, CMU MSML, and JHU MS Data Science.

Complementary Prerequisite Views
The graph contains two prerequisite structures:

prerequisite (skill → skill): Conceptual dependencies between skills, e.g., "Linear Algebra is needed for Statistical Learning"

course_prereq (course → course): Curricular ordering, e.g., "Take C04 before C14"

These are complementary, not redundant. Courses bundle multiple skills, so course prerequisites don't derive directly from skill prerequisites.

Example Usage
library(igraph)
library(dplyr)

# Load the data
data(learning_graph)

# Build skill prerequisite DAG
prereq_edges <- learning_graph$edges$prerequisite |>
  left_join(learning_graph$nodes$skills, by = c("skill_from_id" = "skill_id")) |>
  rename(from = skill_name) |>
  left_join(learning_graph$nodes$skills, by = c("skill_to_id" = "skill_id")) |>
  rename(to = skill_name) |>
  select(from, to)

g_skills <- graph_from_data_frame(prereq_edges, directed = TRUE)
plot(g_skills, layout = layout_with_sugiyama(g_skills)$layout)

# Build course prerequisite DAG
course_edges <- learning_graph$edges$course_prereq |>
  left_join(learning_graph$nodes$courses, by = c("course_from_id" = "course_id")) |>
  rename(from = course_tag) |>
  left_join(learning_graph$nodes$courses, by = c("course_to_id" = "course_id")) |>
  rename(to = course_tag) |>
  select(from, to)

g_courses <- graph_from_data_frame(course_edges, directed = TRUE)
plot(g_courses, layout = layout_with_sugiyama(g_courses)$layout)

Schema
The LearningGraph schema defines permissible node types, edge types, and their constraints. Access it via learning_graph$metadata$schema.

Edge Type	Source	Target	Property	Semantics
has_skill	learner	skill	proficiency	current_level
requires_skill	work_role	skill	proficiency	minimum_threshold
prerequisite	skill	skill	-	-
teaches	course	skill	proficiency	maximum_ceiling
skill_in_competency	skill	competency	-	-
Note that proficiency appears in three edge types with different semantics:

has_skill: Current state (where the learner stands now)

requires_skill: Threshold (minimum acceptable level for role)

teaches: Ceiling (maximum level the course can develop)

The prerequisite edge carries no proficiency property. This is a deliberate design choice: conceptual dependencies between skills are stable regardless of proficiency level.

The skill_in_competency relationship is normalized into the skills table via the cmp_id column rather than stored as a separate edge table, since each skill belongs to exactly one competency.

Temporal Considerations
The LearningGraph as provided is a snapshot: it captures the state of learners, courses, and requirements at a moment in time. A production system would need temporal constraints governing valid state transitions. For example, demonstrated proficiency should not decrease without reassessment. Such temporal extensions are left as an exercise.
